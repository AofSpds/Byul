## High-fidelity interpretation

At the `PERSONA / SOURCE DOMAIN` scope, the Owner clarifies that stored memory/experience data is expected to be the **practical primary source** for Persona formation, but it is not the conceptual boundary of the Persona source domain.

Current concept:

- stored past memory / experience / accumulated state is the main practical source for Persona construction;
- however, in principle, any relevant relation may become Persona source material;
- this can include current context, present interactions, goals/purposes, roles, environment, external world relations, incoming observations, and other relation-bundles;
- therefore Persona source is not a closed fixed dataset or one dedicated memory table;
- the practical challenge is selection/composition: which of the potentially available relations a Persona-forming View uses at a given moment/scope.

Conceptually:

```text
POTENTIAL PERSONA SOURCE DOMAIN
  = stored memory / experience / accumulated state      [main practical source]
    + current context / interaction
    + purposes / roles
    + environment / external relations
    + observations / other reachable relation-bundles
    + ... conceptually open

               ↓ Persona-forming VIEW

        selected / composed relation-bundle
               ↓
             Persona
```

## Important distinction

Do not collapse:

`POTENTIAL SOURCE DOMAIN`

into:

`ACTIVE SOURCE SET USED BY A PARTICULAR PERSONA VIEW`.

The first may be conceptually broad/open; the second is expected to be selective and View-conditioned.

This distinction connects directly to the prior research target of discovering what to preserve, combine, or discard.

## Guards

Do not infer:

`EVERYTHING IS POTENTIAL SOURCE -> EVERY RELATION MUST BE LOADED OR USED AT RUNTIME`.

Do not infer:

`MEMORY IS MAIN SOURCE -> PERSONA IS ONLY MEMORY RETRIEVAL`.

Do not infer:

`OPEN SOURCE DOMAIN -> NO BOUNDARIES OR ACCESS CONTROL IN IMPLEMENTATION`.

Concrete availability, permissions, cost, privacy, retrieval, and runtime boundaries remain implementation questions.

## Research consequence

The next Persona question should move from source-domain membership to **source selection**:

> Given a conceptually open source universe, how does a Persona-forming View decide which relations become active inputs for the current Persona projection?

This should be asked under explicit scope `PERSONA / SOURCE SELECTION`, not as a worldview question.
