## High-fidelity interpretation

This refines the earlier shorthand `VIEW ~= relation / relation bundle`.

The Owner's current intuition is more specific:

- relations have properties / relational characteristics;
- among those characteristics, there may be a class of properties/capabilities that we call `VIEW`;
- a relation (or relation bundle) exhibiting those properties can function as a perspective for interpreting, routing, composing, abstracting, or projecting other relations;
- therefore `VIEW` need not be an external meta-layer or a permanently separate ontological object class;
- `VIEW` may instead be a role/capability/property pattern within the same relational substrate.

Conceptually:

```text
RELATION / RELATION BUNDLE
    + properties
        +-- ordinary relational properties
        +-- VIEW-like properties
                -> can function as a perspective over other relations
                -> can support routing / composition / abstraction / resolution / temporal treatment / equivalence assumptions
```

The exact set of properties that qualifies something as a View is not yet defined.

## Important distinction

Do not collapse this into either of the following without further evidence:

```text
VIEW = JUST A FIELD ON A RELATION RECORD
```

or

```text
VIEW = A SPECIAL ONTOLOGICAL ENTITY OUTSIDE RELATIONS
```

The Owner's current hypothesis is closer to:

```text
VIEW = A RELATIONAL ROLE / PROPERTY CONFIGURATION
THAT CAN ACT AS A WORLD-PERSPECTIVE
```

The implementation may later encode this using records, functions, rulesets, graph structure, higher-order relations, queries, or another mechanism. No representation is fixed by this note.

## Relation to previous hypotheses

This remains compatible with:

- all digital models being abstractions / Views rather than reality itself;
- variable abstraction resolution;
- complex View routing;
- relation bundles being recomposable in multiple forms;
- View/Ruleset/Persona/Organization being interpretable relationally;
- `same View` requiring declared scope/equivalence/temporal abstraction rather than absolute identity.

It also suggests that future View design should focus on discovering **which relational properties make a relation/bundle usable as a perspective** rather than prematurely defining a standalone View object schema.

## Research consequence

A sharper research program is:

> Identify the smallest and most useful set of relational capabilities/properties that allow some relations or relation bundles to operate as Views over other relations, at variable resolution and scope.

Candidate dimensions remain exploratory:

- scope / boundary;
- routing / selection;
- composition / grouping;
- abstraction resolution;
- temporal treatment;
- distinction / equivalence / invariance;
- purpose / task context;
- lifecycle projection;
- provenance / evidence / uncertainty;
- ability to consume and emit relation bundles recursively.

These are research dimensions only, not an approved View schema.

## Guard

Do not infer:

`EVERY RELATION IS ALWAYS A VIEW`.

The Owner states that some relational properties may make a relation/bundle function as a View.

Do not infer:

`VIEW PROPERTY SET IS FIXED`.

The defining property set itself is now a research question.

Do not infer:

`VIEW AS RELATIONAL PROPERTY -> NO EXPLICIT VIEW REPRESENTATION MAY EXIST`.

An implementation may still materialize or name a View for practical reasons; that materialization would itself be another View/representation under the current hypothesis.
