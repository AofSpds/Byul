# 9. Causal Set Theory — Why It Became Important

기본 구조:

# 10. Link

`a≺b`이고 중간에 `z`가 없어 `a≺z≺b`가 성립하지 않으면 Link(직접 인과 연결).

예:

`A→B→C`

- A→B: Link
- B→C: Link
- A≺C: 참이나 Link 아님.

Hasse diagram에서는 Link만 그릴 수 있고 나머지 order는 transitive closure로 복원 가능.

중요 correction:

- Causal Set Link는 Owner의 `최소 국소 사상`과 같지 않다.
- Link는 transformation semantics(무엇이 어떻게 변했는지)를 가지지 않는다.
- `local`은 공간적 nearest-neighbour가 아니다.
- Lorentzian causal set에서는 한 사건이 비국소적인 Link 이웃을 많이 가질 수 있다.
- 표준 Causal Set의 primitive를 반드시 Link라고 단정할 수 없고 partial order에서 도출될 수 있다.

현재 비교:

- Owner local mapping ≈ 작은 실제 transformation
- Causal Link ≈ 중간 causal event가 없는 direct causal-order adjacency

# 11. Chain

Chain = 모든 사건이 causal order로 비교 가능한 집합.

예:

`A→B→C→D`

A-D 사이 여러 chain 중 longest chain을 proper-time-like quantity의 discrete analogue로 사용.

왜 shortest가 아니라 longest인가:

상대론적 spacetime에서 timelike geodesic이 두 timelike-separated event 사이 proper time을 최대화하는 성질과 연결.

중요:

- 3 links = 3 seconds가 아님.
- event density, dimension, continuum approximation, scale factor 등이 필요.
- chain length convention은 element count인지 link count인지 명시 필요.

Owner worldview와 차이:

- Owner: 변화 `m1,m2,m3`가 의미적으로 합성될 수 있음 `m3∘m2∘m1`.
- Causal Set: causal order가 transitive하게 이어짐 `A≺D`.

`변화의 합성`과 `인과순서의 추이성`은 다름.

# 12. Antichain / No Absolute NOW

Antichain = 서로 causal order로 비교 불가능한 사건 집합.

예: `{B,X}`에서 `B≺X`도 `X≺B`도 아님.

중요:

- 절대성에 대한 반대.
- 다만 causal order와 proper-time-like relation까지 임의적인 것은 아니다.

# 13. Causal Interval / Causal Diamond

두 사건 p,q에서 `p≺q`일 때:

`Interval(p,q) = {x | p≺x≺q}`

연속 시공간의 Alexandrov interval / causal diamond에 대응.

중요:

# 15. Reconstruction Reliability / Degradation

Owner가 강하게 제기한 질문:

> 추상화 방법은 매력이 넘치는데 어디까지 복원이 가능한가. 결국 복원에 신뢰성이 없이 열화가 된다면?

현재 구분:

### EXACT
원본 causal structure에서 deterministic하게 복원 가능.
예: Link → full causal order.

### ANCHORED
실측/정확한 anchor로 복원 오차를 제한.
예: exact timestamp/position/state digest anchor.

### STATISTICAL
거시 geometry처럼 통계적/점근적으로 복원.

### VIEW-DEPENDENT
Object/Persona/고수준 view처럼 목적·관점에 따라 materialize될 수 있음.

### NON-RECOVERABLE
원본에서 버린 정보. 예: `A --m--> B`에서 m을 버리고 `A≺B`만 남기면 transformation semantics는 복원 불가.

- 일반 유일성 문제는 완전히 해결된 것으로 취급하지 않음.

Owner가 요구한 보완 방향:

- reconstruction drift를 anchor/checkpoint로 제한.
- derived reconstruction을 다시 ground truth 원본처럼 사용해 `추정→추정 기반 추정`으로 누적열화시키지 않음.

- 상호보완 모델 필요성.

# 16. Complexity Warning — Link-only != Always Cheap

중요 correction:

Causal Set이 의미론적으로 최소라고 해서 storage/compute가 자동으로 싸지 않음.

일렬 chain에서는 N events에 Link가 N-1개 정도지만, 두 층의 모든 상단 event가 모든 하단 event에 Link로 연결되는 구조에서는 Link 수가 대략 `N²/4`까지 가능.

따라서:

- full order relation은 O(N²)까지 갈 수 있음.
- Link representation도 최악에는 O(N²) 수준 가능.
- Causal Set은 자동 경량자료구조가 아니라 **의미론적 추상화**로 평가해야 함.

Owner 정리의 수정된 안전 표현:

> 공간 좌표와 절대시간이 중요하지 않고, 대신 무엇이 무엇보다 causal하게 앞서는지가 정확해야 하는 상황에는 매우 매력적이다.

`시간의 엄밀성이 필요없다`가 아니라:

- causal order는 엄밀히 보존.
- exact metric time / absolute NOW / coordinates를 primitive에서 제거.

# 17. Cycle Question

Causal Set의 causal order는 cycle을 허용하지 않는다.

`A≺B`이고 `B≺A`는 불가.

하지만 현실의 feedback/cycle을 높은 시간해상도로 보면:

`A0 → B1 → A2 → B3 → A4 ...`

일 수 있다.

따라서 중요한 구분:

1. `Causal Event Cycle`: 동일 event로 돌아감 → Causal Set에서 금지.
2. `State / Pattern Cycle`: 같은 state type/pattern이 새로운 occurrence에서 반복 → 가능.

강한 문장 후보:

> Event는 순환하지 않아도 Pattern은 순환할 수 있다.

이 지점에서 Petri Net/LTS 계열과 Causal history의 상호보완성이 드러남.

- Place(장소/조건)
- Token(토큰/자원)
- Transition(전이)

Petri Net은 가능한 behaviour를 작은 구조로 압축하고 cycle/resource/concurrency/synchronization을 자연스럽게 표현.

`A↔B` 가능한 반복 구조를 작은 net으로 표현 가능.

반면 실제 occurrence history는:

`A0→B1→A2→B3...`

로 펼쳐짐.

현재 핵심 구분:

> Petri Net = 무엇이 일어날 수 있는가를 압축
> Occurrence/Causal History = 실제로 무엇이 일어났는가를 전개

Petri Net은 단순 Index가 아니라 executable behaviour model에 가깝다.

을 분리해 볼 수 있어 Owner의 `함수/규칙/구조 자체가 변한다` 직관과 비교 가치가 높음.

# 20. Reverse Compatibility / Synthesis

Owner 질문: 역방향 호환은 불가능한가?

현재 판단:

- 전부 불가능한 것은 아님.
- 그러나 대부분 exact inverse보다 reverse synthesis.
- 같은 observable behaviour를 만드는 원본 표현이 여러 개일 수 있어 비유일성 존재.

호환 등급 후보:

- `EXACT`
- `SEMANTIC`
- `APPROXIMATE`
- `NON-RECOVERABLE`

예:

- Petri → LTS: 비교적 자연스러움.
- LTS → Petri: 조건부 synthesis 가능 계열 존재.
- Petri → Occurrence: unfolding 가능.
- Occurrence → Petri: folding/synthesis는 비유일 가능.
- Event Structure → causal-order: 쉬움.
- causal-order → 원래 Event Structure: conflict/label/resource 등을 버렸다면 일반적으로 불가.

따라서 변환 여부를 Boolean으로 보면 안 됨.

# 21. Index Complement Concept

Owner가 `index의 보완 개념으로 볼까?`를 제안.

현재 해석:

Occurrence / Fact Plane이 실제 발생 원본을 보존하고 목적별 semantic index/view를 만들 수 있음.

예:

- Causal Index: ancestors/causal reachability 질의 최적화.
- Concurrency/Conflict Index: 독립/충돌 질의.
- State/Reachability Index: current state에서 reachable behaviour 질의.
- Metric/Object/Persona View: 목적별 고수준 렌더링.

그러나 Petri Net은 실제 history index가 아니라 **possible behaviour model**이므로 별도 Behaviour/Rule Plane으로 보는 편이 안전.

현재 강한 후보 구조:

`Occurrence/Fact Plane ↔ Behaviour/Rule Plane`

그리고 Situation Router가 필요할 때 semantic model/index/view를 선택.

# 23. Situation Routing — Very Strong Candidate

현재 후보:

`R(S, M, L) → {Target Model Set, Transformation Path, Preservation Contract, Validation Plan}`

# 25. Compatibility / Complementarity Evaluation

후보 모델 간 평가 축:

1. Fitness — 상황에 자연스럽게 맞는가.
2. Preservation — P-series와 상황상 필수 semantics 보존 여부.
3. Mutation Cost — 다른 formalism으로 변환 비용.
4. Round-trip Loss — `A→B→A'` 후 의미차이.
5. Coexistence — 같은 현상을 여러 representation/view로 공존 가능 여부.
6. Reverse Synthesis Success.
7. Invalidation Radius — local mutation 시 얼마나 재계산해야 하나.
8. Query Gain — 해당 representation/index로 질의가 얼마나 빨라지는가.

변환 비용을 한 숫자로 합치면 안 됨.

최소 분리:

- COMPUTE COST
- SEMANTIC COST
- MAINTENANCE COST
- REVERSIBILITY
