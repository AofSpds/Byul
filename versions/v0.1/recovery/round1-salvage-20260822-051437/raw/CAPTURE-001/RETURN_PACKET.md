MINIMAL_PROBLEM_DEFINITION =
Given partially ordered research inputs and editorial/modeling actions, reproduce exact sources and any committed research state; retain provenance, scoped epistemic class, unknowns, conflict, retraction, and supersession; materialize versioned purpose-specific views; reject paths that lose required meaning; and support branch, merge, migration, invalidation, rollback, and recovery without rewriting history. Encoding the whole world or choosing one universal formalism is outside the minimal target.

PHASE1_PROPOSAL =
Adopt an evidence-preserving ledger with contracted materialized views:
1. Content-addressed immutable artifact store for exact source bytes and anchors.
2. Append-only decision journal whose records have typed payloads, authority scope, schema version, optional effective time, and zero/one/many causal parents. Journal lineage is not automatically real-world causality.
3. Immutable claims with scoped epistemic classes; retraction, supersession, disagreement, and resolution are new records rather than destructive updates.
4. W3C-PROV-like dependency records connecting every output to input commit, transform version, parameters, environment, and output digest.
5. A transform/view registry declaring input schemas, preconditions, semantic preservation vector, loss, determinism, costs, invalidation dependencies, and genuine reverse operations.
6. Disposable SQL/Datalog and specialized model projections. Petri/Event/LTS/Causal/metric representations are plug-ins selected only when their semantics answer the query.
7. A contract-driven route planner that searches admissible transformation paths and returns losses, costs, validation, and unresolved preconditions; otherwise REVIEW_REQUIRED / UNKNOWN.
8. Minimal implementation in SQLite or PostgreSQL plus a filesystem/object blob store; no universal hypergraph engine is initially required.

- W3C-PROV-style entity/activity/agent derivation lineage.
- Truth-maintenance/assumption-based ideas for support, alternatives, and explicit conflict.
- Relational/Datalog materialized views for deterministic projections.
- Compiler-like pass/IR contracts for transformation capabilities, preconditions, and loss.
- Petri/Event/LTS/Causal/metric formalisms as task-specific semantic models.
This combines prior art and is not presented as a new theory.

AUTHORITATIVE_REPRESENTATION =
- Source authority: immutable source artifact bytes plus acquisition metadata.
- Decision authority: journaled owner/editor/agent decisions within declared scope; authority about what was decided is not proof of universal truth.
- Model-definition authority: exact versioned transform/model contracts and executable definitions.
- There is no single universal authoritative representation.

DERIVED_REPRESENTATIONS =

PRESERVATION_CONTRACT =
Track source payload/span, provenance/authority, epistemic class/scope, claim identity and lineage, journal partial order/conflict, transformation labels, causality/concurrency/conflict, resource/capacity, composition interface, metric/clock anchors, and schema/transform version independently. Each transform grades each dimension EXACT, SEMANTIC, APPROXIMATE, DROPPED, or UNKNOWN. A path receives the weakest grade of its edges. Semantic equivalence requires a declared equivalence relation and tests; approximate reconstruction requires anchors, error measures, and confidence.

LOSS_AND_NON_RECOVERABLE =
- Causal-order views cannot recover dropped transformation labels, resources, metrics, or alternatives.
- LTS reachability generally cannot uniquely recover the originating behavior model or resource interpretation.
- Summaries cannot recreate omitted wording, ambiguity, tone, or source spans.
- Presentation order cannot establish causality; hashes establish identity/integrity, not truth.
- A DROPPED dimension cannot later be called reconstructed without a new authoritative or anchored input.
- Merge resolution does not justify deleting competing inputs or histories.

TRANSFORMATION_PATHS =
- Every path is an ordered set of registered transforms over an exact input commit.
- Identity tuple: input commit digest, transform ID/version, parameter digest, output digest.
- Admission requires all requested semantic dimensions to meet their minimum grades and all preconditions to be satisfied.
- Reverse synthesis is distinct from exact inverse and is marked non-unique when applicable.
- Derived outputs never mutate the ledger and may be discarded/rebuilt.

LIFECYCLE_BEHAVIOR =
- MUTATE: append assertion/classification/supersession/retraction/transform records.
- COMPOSE: make multi-parent commits with explicit interface/namespace mappings and validate contracts.
- SPLIT/DIVERGE: create branch references sharing exact history.
- MERGE: union histories, surface conflict, and append explicit resolutions; no silent last-write-wins.
- MIGRATE: keep old records and add a versioned adapter/transform, mapping, loss vector, and tests.
- RECOVER: verify artifact/journal hashes, restore commits and transform registry, then rebuild disposable views.
- ROLLBACK: move a reference or append a reverting decision, never delete intervening history.
- INVALIDATE: traverse reverse dependencies and measure affected closure as invalidation radius.
- SUCCESSOR/RETIRE: freeze definitions and record successor plus migration/preservation contract; run numbering does not promote the model version.
