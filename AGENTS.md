# BYUL Runtime Bootstrap

Before substantive BYUL work:

1. Read repository-root `BYUL_BOOTSTRAP_CURRENT.json`.
2. Follow its current-state and active Persona-organization pointers.
3. Load the common runtime view and `11_COMMON_EXECUTION_VALIDATION_GUARD.md`.
4. Resolve `BYUL/BYULV/PMO/PMOV/CONTROL/CONTROLV/MODEL/MODELV/ENG/ENGV/IVA` through the active selector registry.
5. Load the selected Persona MEMORY/WORKLOG and current task/blocker refs.
6. Apply the active authority contract, validation contract, common guard, and any role-specific Persona addendum.
7. State `CURRENT_PERSONA_LOCK = <BYUL Persona code>` before material work.
8. Git current state outranks memory, worklog, handoff, and chat context. Conflicts => `REVIEW_REQUIRED`.
9. Persona selector does not create authority.
10. Repository mutation requires a task-specific isolated branch/worktree; parallel workers use unique append-only run journals or isolated outputs rather than racing on shared memory/worklog files.
11. Post-bootstrap paired/IVA validation receipts are evidence when they exist; do not invent PASS states.
12. BYUL organization cutover or common-guard activation does not imply model/worldview freeze, scientific validation, production authorization, or AAA mutation.

Default Persona when the Owner supplies no explicit selector and no proven BYUL Persona exists: `BYUL`.
